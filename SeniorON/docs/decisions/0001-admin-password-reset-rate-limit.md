# 관리자 비밀번호 찾기 발송 제한에 기존 이메일 인증 발송 제한 재사용

상태: 승인됨 · 2026-11-09 · 결정 주체: 코디네이터 (429 문구 유지는 사용자 확인)

## 맥락

관리자 비밀번호 찾기(`POST /api/admin/auth/password-reset`, #642)는 인증 없이 호출되는 메일 발송 API라 이메일·IP 기준 발송 횟수 제한이 필요했다. 이슈 작성 시 제안한 기본값은 같은 이메일 60초 1회·하루 5회, 같은 IP 10분 10회였다. 이 값을 그대로 쓰려면 관리자용 제한 기록 테이블과 마이그레이션이 새로 필요하다.

## 선택지

1. 관리자 전용 발송 제한 테이블을 새로 만든다 (마이그레이션 추가, 제안한 기본값 적용)
2. 사용자 이메일 인증에 쓰는 `EmailVerificationRateLimitService`를 재사용한다 (마이그레이션 없음)
3. 메모리 기반 제한을 둔다 (인스턴스 재시작·블루그린 전환 시 초기화)

## 결정

2번. `AdminInvitationService.requestPasswordReset`이 계정 조회 전에 `EmailVerificationRateLimitService.checkAndRecord(email, clientIp)`를 먼저 호출한다.

## 이유

- 마이그레이션 없이 DB에 기록되는 제한을 바로 쓸 수 있다.
- 계정 존재 여부와 관계없이 먼저 호출하므로, 제한 응답으로 계정 존재가 드러나지 않는다.
- 관리자 이메일과 일반 사용자 이메일이 겹치는 경우가 드물어 카운터 공유의 영향이 작다.

## 결과

- 제한 값은 기존 서비스 값을 따른다: 같은 이메일 60초 1회·10분 3회·하루 20회, 같은 IP 10분 10회.
- 제한 초과 시 기존 429 오류(`EMAIL429_1`~`EMAIL429_4`)가 그대로 나가며, 문구가 "이메일 인증 코드" 기준이다. 사용자 확인 후 현재 문구를 유지한다.
- 관리자 전용 값이나 문구가 필요해지면 1번으로 전환한다.
